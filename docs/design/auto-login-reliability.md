# 自动登录保存与重试

跟踪任务：[GitHub Issue #3](https://github.com/StevenHuangYH/CUNY-Plus/issues/3)。

状态：实施完成。新增 16 项登录测试，全项目 39 项测试、类型检查、格式检查、生产构建及 ZIP 打包通过。产物中的登录脚本与权限已核对，Standards 和 Spec/security 独立审查均无未解决项。

## 问题与规则

基线 `28b91ec` 的弹窗在存储写入失败时仍显示 Saved，关闭自动登录时也没有等待写入成功。登录脚本在整个 SSO 标签页会话中只记录一个永久尝试标记，因此修正凭据后仍无法重新自动登录。

- 读取设置失败时显示可重试错误，读取成功前禁止编辑。
- 保存成功后才显示 Saved；失败时保留输入，允许重试。编辑后清除旧的成功提示。
- 关闭开关会一起保存禁用状态及清空凭据；写入成功后才关闭界面并清空输入。写入期间禁止相互冲突的保存或开关操作。
- 每次主动保存生成一个新的随机设置版本。版本不包含用户名、密码或凭据摘要。
- 同一 SSO 标签页会话中的当前保存版本只自动提交一次。重新保存可请求一次新的尝试；错误重定向不会自动重试。
- 填写期间发生相关设置变化、页面卸载、表单移除或禁用时，旧任务不得继续提交。提交前再次核对已保存设置。
- 禁用判断包含祖先 fieldset；短暂禁用或移除后恢复也不会恢复旧任务。页面通过浏览器后退缓存恢复时，会重新接收显式保存请求，并继续保留已提交版本的保护。
- 缺少完整同表单的用户名、密码、提交控件时不尝试；不处理 MFA 页面。初始页面没有表单时，可在表单就绪后重新保存或刷新页面。
- 存储读取或会话尝试标记不可用时不提交。日志不记录凭据或原始存储错误。

## 代码边界

`src/features/login/settings.ts` 负责读取类型规范化、保存开关与凭据，以及生成设置版本。保持原有 `chrome.storage.local` 存储位置和权限。

`src/features/login/auto-login.ts` 管理设置变化、异步填写、提交前校验、会话尝试标记及页面卸载清理。`src/contents/content-login.ts` 保持 CUNY SSO 域名配置并启动该流程。会话存储只写入非敏感版本，旧的 `"1"` 标记在首次重新保存前仍有效。

弹窗负责输入与保存反馈；测试通过实际弹窗交互和登录内容脚本入口观察行为，仅模拟 Chrome 存储、时间和平台存储失败。

## 验证范围

使用合成凭据和本地 DOM 验证保存失败、禁用失败、初始读取失败、重复写入保护、显式重试、旧任务取消、MFA/不完整表单跳过及旧会话兼容。没有读取用户真实凭据，也没有提交真实登录。

真实 Chrome 与线上账号验收沿用用户的跳过决定，不记为已经执行的测试。此变更不更改教授评分规则或生产权限。
