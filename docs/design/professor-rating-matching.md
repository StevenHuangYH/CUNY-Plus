# 教授评分查询设计

状态：实施完成，22 个自动化测试及类型检查通过。独立审查的 Standards 与 Spec 两个方向均无未解决项。真实浏览器及线上页面验证尚未完成。

跟踪任务：[GitHub Issue #1](https://github.com/StevenHuangYH/CUNY-Plus/issues/1)。

## 要解决的问题

基线提交 9e29346 默认选择第一个搜索结果，或第一个学校名称符合 CUNY 关键词的结果，却用课程页面上的姓名为评分命名。基线中查询取得的候选姓名没有参与核对，课程校区也没有传入查询。

目标是让教授身份的判断、评分归属和失败处理集中在一个教授评分查询 module，显示端不再自行猜测结果含义。领域用语见 ../../CONTEXT.md。

## 已确认的产品规则

1. 只有姓名和校区都能明确对应，才自动展示评分。
2. 无法确定对应关系时，显示候选教授的姓名、学校和个人主页链接；用户选中后再展示评分。
3. 用户选择仅保留在当前页面，并绑定当时的教授姓名与校区；刷新或课程信息改变后重新匹配。
4. 跨校区及非 CUNY 候选可以展示，但必须由用户明确选择。

## 完整行为提案

| 场景                                       | 预期行为                                                             |
| ------------------------------------------ | -------------------------------------------------------------------- |
| 唯一候选的完整姓名与校区明确对应           | 自动展示该候选的评分                                                 |
| 多个不同教授档案同时满足对应条件           | 展示候选列表，不根据搜索顺序选择                                     |
| 校区缺失或无法辨认                         | 可以搜索和展示候选，禁止自动匹配                                     |
| 姓名存在缩写、拼写差异或无法明确解释的格式 | 展示候选供确认，不把相似程度当成身份确认                             |
| 只有跨校区或非 CUNY 结果                   | 标明实际学校，等待用户选择                                           |
| 用户选择候选                               | 卡片显示所选档案的真实姓名、学校、评分和主页链接，并保留更换候选入口 |
| 用户关闭后在同一页面、相同课程上下文中重开 | 保留本次选择                                                         |
| 姓名或校区改变，或页面刷新                 | 清除旧的选择和显示状态；旧请求的迟到响应不能覆盖新的课程上下文       |
| 没有候选                                   | 显示无匹配结果，提供 RMP 搜索入口                                    |
| 网络、超时或远端响应错误                   | 显示查询失败及重试入口，不谎报为无匹配结果                           |
| 档案存在但部分评分不可用                   | 对缺失指标显示 N/A，不将缺失值解释为 0 分                            |
| 空姓名、Staff、TBA 等占位内容              | 不展示评分按钮，不发起查询                                           |

姓名规范化只消除不改变身份的形式差异，例如空白、大小写和已支持的开头头衔。缩写、缺失的姓名部分和相似拼写不构成自动匹配证据。

校区对应使用明确、可测试的学校名称或别名。禁止通过包含 hunter、cuny 等片段就认定是当前课程校区；未知对应关系按无法确认处理。候选列表显示实际返回的学校名称。

在比较候选数量前，按教授档案标识去重；不同档案不能仅因姓名相同而合并。自动匹配是按可用证据得出的对应关系，不宣称已证明现实中的身份。

当前仓库没有多人授课或复杂姓名格式的真实页面样例。第一轮保持单个课程教师上下文；无法可靠解释的内容不通过猜测拆分成多位教师，也不自动匹配。

## Module 的职责与 interface

### 课程页面 adapter

- 从同一课程上下文读取教师姓名和校区，避免取到相邻课程的学校信息。
- 现有 test.html 支持通过共同的 td 找到 .campus_block；其他结构找不到校区时，返回校区未知。
- 课程上下文变化时重置显示并忽略过期查询结果。

### 教授评分查询 module

interface 的输入是课程教师姓名及可选校区；输出明确区分自动匹配、待选候选、无候选、查询失败和占位内容。

- 集中姓名规范化、校区对应、候选去重、匹配判断和结果完整性检查。
- 候选身份信息与其评分始终来自同一个教授档案。
- 区分数据缺失、没有匹配和请求失败。
- 将远端数据格式留在 implementation 内，调用者只理解上述结果含义。

保留现有查询代码中已经有价值的实现，逐步把散在调用者中的规则收进来。避免再增加只转发调用的 shallow module。

### 环境 adapter 与 seam

- Chrome 消息 adapter 负责输入校验及消息传递，不自行决定哪个教授最合适。
- 远端请求 adapter 负责通信、有限超时及读取响应；测试通过同一个 seam 提供确定性响应。
- 不为假设中的其他评分网站引入通用供应商框架。

### 评分显示

- 根据查询结果展示评分、候选、无结果或失败状态。
- 用户选择只保存在当前页面的运行状态中，不新增持久存储权限或长期教授映射。
- 自动匹配和用户选择均使用候选的真实姓名和学校，避免把页面输入姓名套在另一个档案的评分上。

## 验收与测试

测试调用者实际使用的 interface，而不是只验证拆出的姓名工具。

1. 正确姓名及校区的唯一结果能够自动展示，即使远端第一个结果是另一个 CUNY 教授。
2. 同名跨校区、缺失校区、姓名缩写和多个同校同名档案进入候选选择。
3. 同一档案的重复结果不会制造假歧义；不同档案不会被错误合并。
4. 用户选中跨校区或非 CUNY 候选后，姓名、学校、主页链接和评分全部来自该候选。
5. 关闭重开保留当前选择；更换课程上下文后不显示旧评分，迟到响应被忽略。
6. 空结果、请求超时、HTTP 错误、GraphQL 错误及不合预期的响应分别得到正确处理。
7. 缺失评分不会显示为 0，现有评分指标及标签统计保持正确归属。
8. 占位教师名称不触发请求。
9. 恢复可运行的本地模拟页路径；生产构建继续仅匹配原有 CUNY 域名。
10. 完成对应行为测试、TypeScript 检查和生产构建；核对生成的扩展权限。

浏览器可用时，再在模拟页核对候选选择、返回列表和错误重试。真实 CUNY 页面结构的覆盖情况与远端可用性必须单独报告，不能用本地样例测试代替线上验证。

## 实施顺序

1. 建立教授查询行为测试与明确的查询结果类型。
2. 集中匹配规则，保留远端通信 seam，并让后台传递完整课程上下文。
3. 接入校区读取和候选选择显示，处理上下文变化及迟到响应。
4. 补齐本地模拟场景与说明，完成检查和改动审查。

本轮聚焦评分归属与候选选择。自动登录重构、通用评分卡框架、长期评分缓存、依赖大升级均不在本轮范围内。

## 基线证据与验证限制

- 基线 src/features/ratings/api/rmp-api.ts 的候选选取未比较返回的 firstName / lastName；返回的 school.id 也未用于匹配。
- 基线 src/features/ratings/components/RMPButton.tsx 只发送 professorName，且卡片标题使用页面姓名。
- test.html 提供了教师与校区同在一个 td 的本地样例，没有真实线上快照或多人授课样例。
- 2462a21 删除了本地页面匹配，但 README 仍要求直接打开 test.html。
- 实施阶段使用确定性远端响应及模拟 DOM 验证匹配、候选选择与上下文变化；未登录 CUNY 或验证实时 RMP 查询。
- 学校名称对照 [CUNY 官方目录](https://www.cuny.edu/about/colleges/)（2026-09-24）建立明确名单；未识别的名称和别名一律要求选择。
- 开发版清单已验证含 CUNY、localhost 和 127.0.0.1 匹配；生产清单必须仅保留原有 CUNY 页面匹配及原有远端请求权限。
- 浏览器工具返回 No browser is available；没有截图、真实视口或真实扩展交互验证。
